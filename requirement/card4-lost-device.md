# 카드 4 — 기기를 잃어버렸을 때: 남길 것

> 원문: 패스키 두 개가 보이는 목록 화면, 하나를 지운 뒤의 로그인 성공과 실패 기록

이 카드는 전부 실제 등록된 패스키와 실제 브라우저 조작이 필요해서, 여기 있는 항목은 전부 배포된 사이트에서 직접 캡처해야 합니다. 순서대로 하시면 됩니다.

## 1. [TODO] 패스키 두 개 등록하기

1. 계정 하나로 로그인
2. Private 섹션의 "이 기기에 새 패스키 추가" 클릭 → 이름 입력(예: "두 번째 기기") → 등록
   - 같은 브라우저/기기에서 두 번째 패스키를 만들 때는 인증 창에서 "다른 기기 사용" 또는 다른 인증 수단(휴대폰 QR, 보안키 등)을 선택해야 새로 만들어집니다. 같은 걸 또 고르면 "이미 등록됨" 취급될 수 있습니다.
3. 패스키 목록에 두 개가 함께 보이는 화면을 캡처 → `card4-two-passkeys.png` (T08-C42, T08-C43 — 이름과 등록일이 각각 보여야 함)

## 2. [TODO] 하나를 지운 뒤 남은 하나로 로그인

1. 목록에서 패스키 하나를 "삭제" (마지막 하나가 아니라 두 개 중 하나이므로 정상적으로 지워질 것입니다)
2. 로그아웃 → 남은 패스키로 다시 로그인 → 성공하는 화면 캡처 → `card4-remaining-login-success.png` (T08-C44)

## 3. [TODO] 지운 패스키로는 로그인 안 되는지 확인

방금 지운 패스키가 여전히 이 브라우저/OS의 패스키 저장소(예: Windows Hello, 구글 비밀번호 관리자)에 남아있을 수 있습니다 — 그 저장소 목록에서 그 항목을 선택해 로그인을 시도해보세요.

1. "패스키로 로그인" 시도 → 자동완성 또는 선택 목록에서 지운 패스키를 골라서 시도
2. 서버가 거절하는 걸 확인 (서버의 `credentials` 테이블에서 이미 삭제됐으므로 `/api/login-verify`가 `unknown_credential`로 401을 돌려줍니다)
3. 개발자도구 Network 탭에서 그 요청/응답을 캡처 → `card4-deleted-passkey-rejected.png` (T08-C45)
4. 브라우저 저장소에도 그 항목이 남아 계속 헷갈리게 하고 싶지 않다면, OS/브라우저의 비밀번호(패스키) 관리 화면에서 직접 지워도 됩니다 (선택 사항).

## 4. 마지막 패스키를 지우려 하면 (T08-C46)

이 앱은 **마지막 남은 패스키는 서버가 삭제를 거부**하도록 만들어져 있습니다 (`api/passkeys/[id].js` — 남은 개수가 1개면 400 `cannot_delete_last_passkey` 반환). 비밀번호 같은 복구 수단이 없는 상태에서 마지막 패스키까지 지우면 그 계정엔 영영 들어갈 수 없기 때문에, 아예 서버 단에서 막는 쪽을 택했습니다 (사용자와 함께 결정한 내용).

1. 두 번째 패스키를 삭제하고, 이제 하나만 남은 상태에서 그 마지막 하나를 또 지워보세요.
2. 화면에 "마지막 남은 패스키는 삭제할 수 없습니다. 새 패스키를 먼저 등록하세요" 안내가 뜨는지 확인하고 캡처 → `card4-last-passkey-blocked.png`
